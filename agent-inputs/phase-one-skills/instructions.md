# 第一阶段 F 执行协议

Version: 0.1.1

本协议用于 skills-extension 当前主 Agent 与接任候选，不叠加普通第一阶段或 E 任务。遵循 SOUL.md 的长期原则，读取当前目标、验收、执行接口、预算和来源，只完成 F。当前 Agent 自行实现并验证本轮任务，不创建普通 worker。

## 从实际能力开始

新 run 使用新任务上下文，沿用选定 E retained 的完整代码、长期记忆和历史索引。核对任务文件与当前输入，更新自身工作区的旧任务说明，不拿 E 完成报告当 F 证据。按问题查阅历史，不加载全部旧对话或重新审计 A–E。

先查真实工具注册、实现和保存逻辑，明确缺口并保存简洁计划，再实施可验证的最小变化。已有 read/write/list 与网页工具可作为基础，但不是自动技能发现、执行或持久化能力的证明；不要重复实现已可用的 E 网页接口。工具名、schema、索引与分派由你设计，保持现有权限，不要求通用插件框架。

## 做一个可复用闭环

从实际重复需求、故障经验或已有来源选取小而有用的研究辅助方法。记录适用输入、预期结果、负例和验证方法；创建轻量索引、说明及必要脚本，使模型能按问题发现、按需读取、判断适用并实际执行。使用第二个适用输入检查复用；不要只让脚本打印成功，也不要把合成结果写成 A3 实验成绩。

将具体执行结果关联实验记忆和 skill，更新证据状态、限制与版本。外部参考、功能检查与比较收益分开，索引要反映当前状态和弃用信息。按需加载，不把全部正文拼入每次请求；没有价值的内容不强行转为 skill。现有来源够用时不联网凑验收，确需联网时遵循本轮部署授权、既有网关和隐私边界。

## 实际加载、保存与交接

修改源码不会自动替换运行中的对象。用现有工具让修改真实加载，当前 Agent 自行用完整源码、工具、固定输入和预期输出执行局部检查。最终保留实现必须与完成检查的代码一致，保存可核对摘要。必要时使用完整候选，但只有实际需要更换主身份才按 /evolution/trials 和 decision 交权；旧主核对 main_owner 改变后再退出，候选被采用后继续，不以测试结束提前退出。

维护自己的清单生成逻辑，显式包含需要传承的技能目录中文件、索引、代码、记忆及必要证据引用；不要假设旧 save_manifest 会递归收集新目录。分别验证 resume 与 continuation 文件完整，并在下一次正常 checkpoint 保存后再次核对。大文件沿用 exports 引用，不把权重、数据或凭据塞进代码包。重载后实际用工具复用保留 skill，不只检查文件名存在。

每代只对自身“提出计划/假设 → 实际检查 → 保留、拒绝或证据不足”的闭环负责；继承前代已确认结论及限制，交接未完成项与恢复入口，不补审全部祖先。局部检查完成后仍须汇总 F 所需的完整证据。

## 反馈、失败与结束

收到 human feedback 时核对人工干预内容、当前输入、权限与实际环境，记录反馈来源、影响及采纳决定，保留旧状态与证据。外部说明不替代本轮真实检查，不得追溯改写测试条件；新信息可能解除旧阻塞，但需按实际结果重新判断，不机械重演旧退出结论。

普通实现错误、负例失败和局部加载问题先自行诊断；对不确定调用检查真实状态，避免盲目重放。确需外部处理时按 execution.md 保存 blocked 的事实、证据与所需操作后退出，不持续调用模型空等。版本输入连续读取前后须 active 且 revision/generation 一致；恢复沿用同 run 的原上下文，只有新任务初始化新上下文。

F 证据完整后保存结果包、checkpoint、记忆、技能和 continuation，再通过程序 return/break 正常结束。若使用自身 stop 接口，先保存全部状态并作为最后操作，不依赖响应后写盘。没有通过则准确保存失败/阻塞/未完成，不把局部成功升级为全项通过；完成后不继续训练、第二阶段或无尽技能扩张。
