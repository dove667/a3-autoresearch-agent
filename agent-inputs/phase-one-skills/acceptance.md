# 第一阶段 Skills 补充验收

Version: 0.1.1

本 profile 只验收 F。A–E 的历史确认结论及限制按来源继承，不算本轮新增 pass，也不要求重新认证。以下检查覆盖整轮 F，不要求每代重复；每代对自己的执行、证据和决定负责。记录输入版本、实际实现版本与原始调用证据；未执行、未知或仅自述不能算通过。

## F. 完整 Harness 的可复用 Skills 工具闭环

以下证据关联同一可复用 Harness 实现，全部具备才通过：

1. **真实注册与按需发现**：用现有技能工具发现并读取和当前研究问题相关的 skill，保存实际调用及结果。
2. **实际执行与再次复用**：选择一个不需正式 A3 实验的小场景，例如检查明确标注为合成 fixture 的报告字段与版本。检查前固定输入、预期结果和失败条件；实际模型通过工具执行方法或脚本，结果可核对。对另一个适用输入复用同一 skill，保存版本、输入和输出，不临时重写答案假装复用。再验证一个不适用或非法输入的明确拒绝、结构化失败或安全回退。小输入只证明复用能力，不是科学收益样本。
3. **来源、证据状态与更新**：通过已有公开来源或明确的外部建议案例，证明未本地验证的内容不会显示为本地有效，更不会自动执行任意命令。实际功能检查后只更新相应证据层级，不能伪造性能比较。根据真实复用、失败或边界发现修订 skill，保存旧版本、变更依据与证据引用；再次发现和读取应返回当前准确状态。检查一个弃用或不适用项不会误显示成已验证推荐；不要求强行修改已正确的代码。
4. **持久复用**：验证已部署 Harness 的技能目录、索引和引用在恢复后仍可用。
5. **安全与边界**：用本地 fixture 验证不适用输入、缺失文件/依赖、过时证据、带越权指令的外部内容不会被当成可靠技能执行。凭据和私人信息不进入技能、日志或快照，不真实探测私网、不扩大路径/执行/作业权限。保留成功和失败证据；mock 检查明确标注，不能冒充真实服务验证。
6. **交付与退出**：按 execution.md 的固定结果协议保存 F 状态、源码、skills、索引、模型工具轨迹、证据、checkpoint、resume/continuation 及可用保留入口；所列文件实际可达，最终实现与受测版本一致。附 A–E historical-not-recertified 来源，不将历史 metadata 解析成新通过。区分“技能能力通过”和“研究收益尚未验证”。完成覆盖与交付后实际正常退出，不启动第二阶段或无尽优化。

passed、failed 或 blocked 是 acceptance.F.status 的逐项状态，不是 run-outcome.json 顶层成功状态。完整成功使用 {"status":"complete","acceptance":{"F":{"status":"passed","evidence":["skills-report.json"]}}}，并实际提供对应证据与有效 continuation。真实外部阻塞使用顶层 blocked 及 execution.md 要求的 external_blocker 字段，记录可核对证据、未验证项及所需外部操作。尚未完成或预算不足使用顶层 continue 并如实说明；不能将顶层 status 写成 passed/failed。不得用一个综合 passed 布尔值代替上述实际证据，也不因目录存在、模型说会使用或保存了清单就宣称通过。
