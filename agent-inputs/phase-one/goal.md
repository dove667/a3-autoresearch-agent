# 第 1 阶段：A3 auto research 与 Harness 优化的适配验证

Version: 0.2.2

从通用 mini-SWE-agent 出发，为第二阶段的 Policy 与 Harness 联合优化建立可运行的起点。本阶段验收四个能力：通过受限接口完成 Policy 实验、根据执行轨迹完成 Harness 反思与改进、在明确权限内执行并与其他实验隔离、在新会话中检索并复用持久保存的历史经验。

本轮固定模型配置，允许改变 Harness。auto research 方向、工具组织、工作流、记忆和搜索方式由运行中的 Agent 根据反馈选择。第一阶段验证两种优化循环、权限边界与记忆复用均能实际运行；不设置性能、效率或成本提升幅度门槛。

## 一轮 Policy 优化

通过 A3 已有接口理解任务与动作契约，调用仿真、相机、策略和评测能力，完成“观察 → 假设 → 候选策略 → 配对实验 → 保留或拒绝”的完整循环。至少完成一次真实改进尝试，允许候选没有收益并被拒绝。

A3 提供 auto research 的环境与评测。保留其物理、动作契约与计分语义，策略候选在本次实验范围内执行。能力证明来自 Agent 在受限运行中实际调用接口、读取结果和推进实验；A3 仓库本身的开发与 pytest 回归由其维护者负责。

真实训练、数据下载与大规模 Policy 性能优化留到第二阶段。

## 一轮执行轨迹反思与 Harness 优化

至少完成“执行并保存轨迹 → 回看自己的历史 → 定位过程问题 → 提出并实施 Harness 候选 → 后续执行使用候选 → 比较并决定保留或回退”的完整循环。

反思引用实际消息、工具调用或实验事件，说明问题、改进假设和预期影响。后续进程或会话实际加载候选并完成任务，记录完成质量、调用次数、可获得的 token、耗时或恢复开销。真实费用不可获得时记为未知。

候选可以被拒绝，保留无改善或退化的证据。第一阶段要求闭环成立；优化幅度与长期效率在第二阶段评估。

## 受限工具与实验隔离

形成供后续auto research Agent 使用的固定权限范围：能够访问所需 A3 接口、修改自己的策略与 Harness 候选、运行自己的实验、读取结果和作出决定。工具名称和数量由 Agent 设计。

正式 auto research 执行经受限工具完成。模型不能通过任意宿主 Bash、Python、SSH 或其他旁路操作共享环境；候选代码及新增工具同样受边界约束。权限由执行层强制落实，覆盖文件、进程、作业、资源和凭据，不能依赖提示词承诺或仅隐藏工具名。

Harness 自我修改不得自行扩大权限。资源分配、权限上限及验收条件由部署方控制；可演化代码在这些边界内试验。用验收专属资源验证跨 run／共享范围之外的读取和未授权写入、取消会被拒绝，同时合法实验及本轮研究数据共享读取可完成。

通用 mini 的冷启动构建过程与生成后的auto research Agent 分别记录权限。冷启动使用的广权限能力只能在部署方隔离的构建环境中使用，不传递给正式 auto research 执行。构建环境本身的权限限制由部署方预先提供。

## 持久记忆与历史经验复用

自行形成适合 A3 auto research 的持久记忆能力：在当前 session 的实际实验、工具使用、失败处理与候选选择过程中，主动判断哪些经验值得保留，写入并维护自己设计的记忆存储。保留能够回到原始证据的引用；后续进程或新会话在没有原始模型上下文时，按当前问题检索这些经验、判断适用条件，并用于行动。

人类提前准备的原始轨迹与产物归档用于追溯和恢复，历史材料也可供 Agent 补充经验。D 项应展示当前执行中的主动记忆写入，再由后续会话检索复用；单独在新会话中整理旧归档不足以完成这条链路。

记忆的组织、写入、更新和检索方式由 Agent 自主决定，可以从简单文件或表格开始，也可以采用数据库、索引或图。无需接入现成系统或联网搜索。能力以实际复用检验，不设置存储方案、摘要模板、检索算法或节省 token 的数值门槛。

历史记录只能在本次分配或明确授权交接的范围内使用。记忆中的历史动作和文字按待核查数据处理，不能扩大当前权限或替代版本化目标。同一 run 的已登记身份共享研究内容的读取；写入及作业管理仍按本身份或已采用 lineage 授权。其他 run、Host 凭据与外部用户数据保持隔离。

## 自主推进与版本

若存在 `/run/input/previous-run.json`，先确认本次沿用的版本，并按需读取其中的历史索引。结束前按 `/run/input/execution.md` 的固定结果协议声明保留入口与启动文件，使下一轮能够直接加载；实验选择与记忆组织仍由 Agent 决定。

Agent 自主从目标推进到验收，不依赖人类逐动作确认、提供下一轮任务或手动加载候选；收到反馈时按本阶段 phase-instructions.md 核对适用性。不设总 step、代数或总运行时间上限。修改源码后让后续执行实际加载新版本，按需组织新进程、会话与磁盘交接。

当前研究 Agent 自己完成 Policy 与 Harness 的实现、数据采集、训练、评估、脚本修复和验收判断。局部检查在本身份工具与远程作业中执行，不创建普通 `/sessions` worker，不采用 orchestrator/worker 分工。完整 Harness 版本只通过 `/evolution/trials` 启动一个线性候选；前任等待候选自测并读取结果，候选交权前仅完成清单并等待，不开展独立研究。拒绝则回收候选并继续原版本；采用则由同一候选接任，旧主保存交接后退出。禁止分叉并行研究 Agent。

互相独立且输入已就绪的远程作业，先在权限与资源额度内并行提交，再统一查询与收集结果；有数据依赖的作业按依赖推进。采集和评估中的独立 episode 统一使用 `/run/a3/episode_executor.py`，由 Agent 固定科学参数、seed、协议与输出；不另写固定两个并发的循环，不重复已完成的科学 episode 测吞吐。

普通脚本、参数、依赖适配和结果解析问题由当前 Agent 在当前任务中定位、修复并验证到底，保留失败与修复证据；需要 Host 凭据、权限、服务或资源配置变更时，保存具体错误、所缺条件和所需操作，明确报告操作者。正常作业等待按状态继续推进。

启动位于 A3 实验工作区；Harness 是独立 Git 仓库，第三方代码独立管理。保留起点、候选、日志和原始产物，不覆盖共享基线，不自动发布或推送。部署信息与凭据保持在版本控制之外，凭据不进入模型消息或轨迹。

## 完成条件

按本次版本化的 `acceptance.md` 逐项验收，保存结果、执行版本和证据。四个核心能力均通过才完成本阶段；失败继续处理，确需外部权限或资源时保存阻塞状态。专项实现由运行中的 Agent 产生。
