# 第 2 阶段：学习型 Policy 与 Harness 联合优化

Version: 0.4.2

本文件定义研究目标、允许的优化范围与不计为收益的做法。完成证据见 acceptance.md，固定科学比较规则见 protocol.md，长期行为见 SOUL.md，接口、恢复与反馈投递见 execution.md；这些文件均由 Host 随本阶段提供。

从明确选定的第一阶段保留 Harness 开始，围绕 A3 两种装盒任务自主开展 auto research：提高学习型机器人 Policy 的闭环评测成绩，同时改进 Harness 的实验效率、token 使用效率和长程可靠性。研究起点包含已有代码、持久记忆与授权历史。

当前研究 Agent 自己完成 Policy 与 Harness 的实现、数据采集、训练、评估、脚本修复和验收判断。局部检查在本身份工具与远程作业中执行，不创建普通 `/sessions` worker，不采用 orchestrator/worker 分工。完整 Harness 版本只通过 `/evolution/trials` 启动一个线性候选；前任等待候选自测并读取结果，候选交权前仅完成清单并等待，不开展独立研究。拒绝则回收候选并继续原版本；采用则由同一候选接任，旧主保存交接后退出。禁止分叉并行研究 Agent。

互相独立且输入已就绪的远程作业，先在权限与资源额度内并行提交，再统一查询与收集结果；有数据依赖的作业按依赖推进。采集和评估中的独立 episode 统一使用 `/run/a3/episode_executor.py`，由 Agent 固定科学参数、seed、协议与输出；不另写固定两个并发的循环，不重复已完成的科学 episode 测吞吐。

普通脚本、参数、依赖适配和结果解析问题由当前 Agent 在当前任务中定位、修复并验证到底，保留失败与修复证据；需要 Host 凭据、权限、服务或资源配置变更时，保存具体错误、所缺条件和所需操作，明确报告操作者。正常作业等待按状态继续推进。

## Policy 优化目标

依据本轮 /run/input/protocol.md，在 2×5、2×10 与 basic、medium、advanced 构成的六格上评测同一个固定 Policy 快照。主要优化六格最终入盒数量的归一化平均分，逐格成绩及完整 success 同时报告。开发迭代可自主选择小子集，结合配对结果和行为过程证据保留中间版本；完整网格用于最终报告，不要求每次改动都跑完 120 回合。

候选保留依据具体能力的实际进步：结合真实录像或抽帧、同步动作与状态轨迹，分析抓取、运输、放置、稳定性和失败恢复，并报告任务分项、样本覆盖与不确定性。有依据的局部改善即保留模型、检查点、配置和证据，总分未涨或完整 success 未增加不自动淘汰候选。视觉迹象尚不确定时保留待验证状态，并针对关键能力补充比较；总体成绩仍按协议如实报告。保留多个具有不同优势的候选，不必先选出唯一优胜者。

优先扩大模型与方法覆盖：核对项目现有可训练策略家族、已有实验和所缺条件，为尚未尝试的可用模型安排有意义的数据量、训练预算和闭环诊断，再依据实际学习与行为表现安排深入优化。小样本负结果不直接否定整个家族，避免连续围绕同一模型做细微改动。独立实验在固定资源上限内并行推进。

模型、训练数据组织、训练或微调算法、模型结构与部署策略由 Agent 自主选择。允许使用项目提供的基座、已有微调模型、公开数据、自采数据及多任务训练。允许直接优化已有模型的部署方式；每项实验说明实际改变了什么。仅切换两个已有规则专家不能作为本阶段学习型 Policy 优化成果。

优先适配、微调已准备且授权的基础模型，先核对权重、backbone、tokenizer 与观测/动作接口；随机初始化的小网络可作链路验证或参考，不占据优化主线。方法仍自主选择，资源缺项准确记录并按 execution.md 处理，不自行下载。A3 仓库开发及其 pytest 回归属于维护者，本轮改进对象是自己的 Policy、Harness 与记忆。

无需限定为“只在 2×5 训练”。确实只用 2×5 数据时，将 2×10 结果标记为迁移测试；使用两类训练数据时如实标记。规则专家用于数据生成、参考和诊断；正式模型比较使用约定的观测接口，推理不读取饼干真值位置、目标槽位真值或专家动作作为隐藏输入。

不得修改 A3 物理、任务、随机化、计数、成功判定或评测条件获取收益。训练损失不替代闭环成绩。

## Harness 优化目标

Harness 的优化对象是实际 auto research 的组织与执行过程。在可比工作负载及相同结果质量下，目标是减少语言模型 token、无效调用、重复实验、等待与恢复开销。Policy 推理开销与负责 auto research 的语言模型调用开销是不同归因对象。

主流程不自行设置总 step 或总代数终止上限，在本轮预算内持续推进；预算不足时按 protocol.md 停止新增实验并保存真实未完成状态。

Policy 与 Harness 两条路径可交叉进行；分别归因，不能把换了 Policy、少跑回合或丢失必要结果计为 Harness 收益。保持已有权限、版本、记忆、恢复和交接能力。

## 持续研究与停止条件

第二阶段是持续研究任务。acceptance.md 的 A–D 是可核验、可交付的研究里程碑，不是完成一次后自动结束整个 run 的条件。达到里程碑后保存固定版本与证据，继续依据真实瓶颈和信息价值选择 Policy 或 Harness 的下一项研究；不为延长运行而制造空转、重复失败或没有信息增益的实验，也不自行设置固定轮数或时间终点。

持续研究期间顶层 run-outcome.json 保持 status=continue，阶段性通过记录在 acceptance 与证据中；保持当前主流程或有效后继，不用全体退出表示等待。正常作业/资源等待可保存状态后低频核查。遇到可恢复异常先诊断，在当前任务中修复并核验，不伪造成功；重大安全、权限或证据完整性风险须停止受影响实验并保存真实状态。明确操作者停止、授权/预算无法继续或真实阻塞时按 execution.md 的既有停止与恢复协议保存 checkpoint、未完成事项及所需动作，不绕过限制，也不把停止原因当作验收通过。

阶段报告冻结 Policy/Harness 快照、比较条件与结论，不随后续研究追溯改写。最终测试只用于已选定快照的报告，不能变成持续研究的调参信号；若其结果被用于后续候选选择或调参，严格按 protocol.md 将已暴露测试集改记开发集并登记新的未使用最终测试集，保留原报告与用途变更记录。未完成全量证据只能报告开发子集，不能提前声明完整验收。

## 研究结果的边界

Policy 与 Harness 的完成状态和收益证据分别报告。允许诚实交付无收益结果；保留基线或拒绝候选不等于研究失败，也不自动证明实验已经完整完成。完整性由 acceptance.md 的实际证据判断，不承诺一定提高性能。

最终研究产物包括学习型 Policy 的固定快照、六格成绩、Policy/Harness 的比较与决定，以及可复跑入口。建议或评价不计为性能与效率收益。
