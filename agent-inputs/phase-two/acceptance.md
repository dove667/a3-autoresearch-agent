# 第 2 阶段验收：学习型 Policy 与 Harness 联合优化

Version: 0.4.2

本文件与本轮 goal.md、protocol.md 共同定义第二阶段验收，通过 phase-two 输入选择加载。

## 代际责任与研究里程碑

以下项目定义持续 run 的能力与交付覆盖，也是可冻结报告的研究里程碑，不是每代重复执行全部验收的门槛，全部通过也不自动结束持续研究。每代在交权前核查自己负责的“假设先于执行 → 实际结果 → 保留/拒绝/证据不足决定”闭环与接任清单，交接各代已确认结论与证据引用、适用条件、版本和明确未完成事项。后继继承已确认结论，无需逐条重审前任；接手未完任务只承担接手后的新执行责任。未完成或未知不得写成已确认。前任历史缺口须标明归属，不因换代消失或自动成为后继的补审责任；存在未覆盖项时不得声明整轮全部通过。

最终主 Agent 核查自身工作并汇总各代结论，不为此前各代重新执行或审计原实验；明确矛盾可针对性核查，原始证据保留供按需查询。科学比较与真实证据要求不变，局部试运行通过不等于整个 run 已通过。

## A. 学习型 Policy 基线与真实改进尝试

- 固定模型、数据/基座来源、处理器、推理配置与版本，建立与所选开发子集匹配的基线。日常筛选和中间版本保留不要求完整开发网格。
- 根据真实结果提出至少一个改进假设，自主选择模型、数据、训练或部署方法，并实际执行候选。选择训练路线时保存真实训练日志与 checkpoint；选择部署路线时如实记录未重新训练。
- 至少一个候选完成与基线同条件、相同场景的真实开发子集配对比较，结合实际入盒数量、完整 success、执行可靠性、真实视频与同步轨迹中的具体能力变化及预登记条件作出保留、继续验证或停止投入的决定；记录覆盖范围与未测条件，完整 G 仅用于已完成的六格 120 回合。切换两个已有规则专家、仅调用 help 或只保存模型文件不完成本项。
- 抓取、运输、放置、稳定性等能力有可追溯改善的候选，保存模型/检查点、配置、适用条件与过程证据；不要求先有总体分数上涨。未确认的过程改善保留待验证状态。汇总不同模型/方法的覆盖、训练规模及后续选择依据。正式总体收益仍按协议报告，过程能力改善按对应证据和范围报告。
- 最终测试集对初始基线和已选定的最终 Policy 各完成 120 回合；最终 Policy 可因候选失败而仍为基线，同一快照和协议的结果可复用。保存原始报告、配对差值、区间与结论，不将证据不足写成确定提升。

## B. Harness 反思、候选执行与选择

引用本轮轨迹的具体问题，给出假设与候选版本，让后续执行实际使用改动。按 protocol.md 完成至少三个配对工作负载实例，比较交付质量、token、调用、错误和耗时，记录保留或回退理由。被采用的完整主 Harness 候选须通过固定交接接口接任；被拒绝的完整候选不要求接任，保留其实际执行、比较和拒绝证据即可判断该闭环。当前 Agent 自行完成局部检查；唯一正式候选仅自测，前任等待结果，采用后同一候选接任继续研究。禁止普通 worker 或多 Agent 分叉。

至少形成一次真实的反思—修改—执行—比较—决定闭环。收益与完成状态分开：无收益或被拒绝的候选仍需完整证据，不能声明效率提升。

## C. 可追溯性、记忆、权限与预算

- 每个正式提出的 Policy/Harness 实验假设均进入 Agent 自己的持久记忆，执行前保存假设与选择条件，结果出来后关联原始证据、状态和决定；暂缓、失败及拒绝的实验同样记录。按 protocol.md 核对写入与实验的先后顺序及条件变更历史。
- 启动、恢复、接任或安排新实验前实际检索相关先例与未完成实验；至少一次后续行动引用取回的假设/结果及来源并据此行动。复验保留理由，已有作业先核对状态。
- 每项实验关联 Policy 快照、Harness commit、数据/协议/输入版本、seed、作业和原始结果，保存失败与拒绝记录。若反馈影响实验安排或解释，将反馈来源/ID、所涉版本、影响及采纳或不采纳的决定关联到这条现有证据链，如实标记人工参与；反馈本身不是实验结果或通过标签。
- 保持既有身份和资源隔离；不更改共享 A3 物理、计分、任务条件或权限上限。模型推理仅使用声明的可用观测；特权专家仅作采集和参考。
- 保存启动预算、已用和剩余资源、训练与评测 GPU 时间、可测语言模型用量及存储占用。不得绕过调度、用未登记作业或超出已授权预算。

## D. 阶段交付与后续可用

按报告快照交付选定的最终 Policy、处理器与代码/配置清单、完整网格报告、Harness 比较与选择、记忆、checkpoint、continuation 和可执行恢复/复跑入口。模型权重和大数据保存在授权的持久存储，以摘要和路径引用，不经小型 JSON 上传接口搬运。

将“优化实验是否完整完成”“Policy 是否有提升证据”“Harness 是否有提升证据”分别写清。预算耗尽但比较或交付未完成时，保留真实未完成状态和可恢复入口；不以预算耗尽充当通过。无候选胜过基线时可保留基线并完成实验交付，不承诺一定提高性能。

Agent 自己执行和判断验收，保存逐项状态与证据。建议、外部评价和完成声明均不能代替本文件要求的真实证据，也不能追溯改写历史结果或当时的验收条件。

持续研究时，即使 A–D 均已有 passed 与对应证据，顶层仍写 status=continue，记录已完成里程碑、当前研究状态和下一步；不因此退出或要求每代重跑同一验收。新增实验沿用相同科学规则，更新其自身状态，不把旧快照的通过标签直接套到新版本。最终测试的冻结与后续用途遵循 goal.md 与 protocol.md，不反复用同一最终测试集筛选候选。

只有 goal.md 的停止条件实际发生时才收尾；能否声明 status=complete 仍取决于本文件的完整证据与有效 continuation，未覆盖项不得因停止而标为 passed。真实外部阻塞按 execution.md 的 blocked 格式报告；其他未完成状态如实保留。Host 不替 Agent 维持下一回合：顶层 continue 且所有进程退出会被记录为 incomplete，而不是持续运行。
