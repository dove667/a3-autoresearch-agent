# 第一阶段 G 执行指令

Version: 0.1.0

只完成当前 G 目标。遵循 SOUL 和 execution.md，核对当前输入、来源与实际工具/代码，先定位请求构建、checkpoint 保存和恢复路径。F 的现有循环逐次追加并发送完整 messages，本轮要让新能力真实进入请求路径，不只添加一个独立摘要演示。

先确定有辨别力的小型 fixture、预期保留事实和失败条件，再自主选择实现。摘要请求本身也受上下文与本轮用量预算约束；必要时分段整理，不能把已经超限的原文一次提交给摘要器。保留部署方当前指令、工具定义等开销的余量，不通过删掉当前目标或验收来节省 token。原始事实与低信任外部内容保留来源和角色。

在工具交互的安全边界整理历史，保持 call ID、调用结果及协议所需项一致。将大工具输出的原文持久化并返回可定位引用可以减少上下文，但仍需证明语义摘要与历史检索。摘要、工作消息、历史位置和保存代次要能一致恢复；不要先覆盖唯一原件再验证摘要。已有实验记忆和 skills 是可复用资产，不因本轮清理工作上下文而删除。

使用现有模型网关、会话、文件和执行接口。工具/模块名称由你设计，不要求新服务、数据库或专用 compact endpoint。测试 worker 只承担主 Agent 明确交给它的局部检查；不用完整 G 目标要求每个 worker 自我进化或交权。可在隔离测试中降低阈值，声明其与实际配置的区别；不要为了验收制造数十万 token 的无意义真实历史。

修改磁盘源码不等于运行对象已更新。使用既有机制加载并验证完整候选，记录受测源码摘要；仅实际需要更换主身份时按现有试运行/交接协议处理，不强制多次换代。最后一次正常 checkpoint 后复核声明文件仍可达。恢复测试围绕固定、足够代表性的压缩后状态；继承结论、当前主对话快照和完整 Harness 源码是不同对象，不能不断追加“必须拿到最新主对话”作为交付门槛。

人工反馈说明干预来源和内容，不是自动通过标签。保留与当前行动相关的反馈及处理状态，区分原始反馈、摘要和新任务指令；压缩/重建后核查反馈是否丢失或被误解，而不是更改 Host 投递接口。只处理真实矛盾，不重新审计全部旧实验。

对实现错误先诊断修复，对不确定调用先查状态。空模型结果、压缩失败或不可用历史应有有界处理和可恢复记录，不能无限空转。证据满足后按固定结果协议交付并正常退出；有外部阻塞准确记录所需操作。G 完成不授权开始第二阶段。
