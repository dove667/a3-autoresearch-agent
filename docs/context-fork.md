# 上下文压缩与记忆（fork / Recall / spill）

`src/a3_research_agent/harness/` 提供可选派生 Harness 的 spill、异步整理和原文回查。
源码同步不代表当前进程已加载；部署须保留原现场并记录人工干预。它们不改变 Host 权限、
A3 物理、评测条件或科学判断。

## 三层处理

| 层 | 实现 | 边界 |
| --- | --- | --- |
| 工具输出归档 | `context/manager.py` | 所有 JSON 结果按完整序列化 envelope 限界，默认每条 12000 UTF-8 字节；原文、哈希和部分预览保留 |
| fork 整理 | `context/compaction.py` | 按 token 预算启动一次完整历史摘要；下一主请求仍须满足硬预算 |
| 回查检查点 | `context/compaction.py`、`memory/recall.py` | 摘要失败时明确未总结，不伪造完成；原文、最新完整工具批次和当前任务必须保全 |

有界 read 页的收据记录原始页；preview 不是完整交付或已理解。字典、列表和转义字符串走同一
入口，显式 Base64 文件响应会生成有来源与哈希的本地解码文件；UTF-8 文件按字符分页，二进制
返回类型元数据。`context/spill.py` 的字符串工具输出使用原子写入及内容校验。

## 安全异步边界

`before_request(messages, extra_messages=[operational])` 先检查消息配对，再检查可用结果。
有安全余量时可在后台启动 fork，同时继续正常决策。工具 schema、操作状态与 Host 注入预留
参与预算。新 Host 分别返回 `trigger_tokens` 软触发和 `decision_input_tokens` 硬准入：
默认在包含 Host 注入、工具和操作状态的输入估计达到 400000 tokens 时后台整理。
500000 配置窗口保留 10% 余量并扣除 8192 输出预留，硬准入为 441808 tokens；
客户端从软、硬预算扣除同一组预留，不再以 85%×400000 提前触发。
压后消息增长 10% 才再次触发；含尾部的发布结果以长度与哈希保存基线，确认或重启后按当前单位重算。
硬准入优先，不能因增长抑制而发送超限请求。
硬预算不够时等待已启动的 fork，默认最多 300 秒（可配置范围 0–300 秒），
仍不满足则保全检查点，不发送已知超限的主请求。

fork 通过 `/v1/summary` 一次提交完整可读历史，一次生成工作记忆。
删除分段、摘要纠正重试、累计调用预算及旧 Host/字节预算兼容。
摘要失败或调用结果不确定时保留原文与状态，不自动重发；最新工具批次仍保持配对。

退出只短暂等待并调用 `apply_ready` 应用已有结果，不启动新的摘要循环。后台未完成的调用
记录为不确定，重启不机械重放。

## 预算单位与配置上限

部署配置的模型窗口是已配置的安全上限，不是上游窗口验证结果或必须填满的目标。
默认主请求触发 400000 estimated tokens、压后软目标 32000。摘要使用完整 500000 窗口，
扣除 8192 输出预留后的输入准入为 491808 tokens，提示词及 provider framing 计入输入；
还须计入 Host 指令与人工通知、工具、操作状态及输出预留。压后目标是软目标，受保护的
完整工具批次可能使结果高于目标；token 模式保留满足目标的最长配对尾部，不先固定裁到六条。
下一请求仍需满足硬预算。checkpoint 的文件字节数
不能替代 tokenizer 计数，继承的旧 context-report 也不能替代当前 /context/config。
注入内容持续增长会挤占有效工作区，甚至使配置不可用；不得为节省 token 擅自丢弃用户约束。

## 模型角色与缓存

`/v1/summary` 只接收完整 `transcript` 和归档来源 `source`，
并选择已配置的 summary 模型和推理参数。摘要无主工具、无完整阶段正文或人工反馈正文；
反馈只给 ID/哈希引用，完整通知仍进入正常决策。旧摘要请求字段会被拒绝。

不会为了尝试 prefix cache 复制主 Agent 的全部 instructions、tools 和历史去普通模型接口。
同模型不保证缓存复用，输入、前缀和服务条件都影响观测。只能用实际返回的 cached_tokens
统计已知样本；未记录与真实 0 必须区分。固定八节是历史格式参考，不是 Host 摘要的硬验收条件。

## 发布、恢复和任务归属

`compaction-result.json` version 2 绑定任务 epoch、原消息前缀长度和哈希、原文来源与
replacement 哈希。应用须核验来源和工具配对；旧任务、异源 checkpoint 或缺失来源不能替换
当前目标。结果返回给调用方后，由真正保存的 checkpoint 确认应用；中断时可幂等重放，不能
先标 applied 再丢失结果。

fork 运行期间新增的工具结果参与合并后的预算检查。需要再限界时，使用同一个无模型归档器，
保留全部 call/result ID，并先持久化绑定当前完整前缀的 `publication` 提案。checkpoint 写入前后
中断均可重放／确认一次，不追加重复尾部或重复摘要请求。等待超时仍保留在途 fork 的前缀身份；
恢复时采用当前操作状态预留，而不是旧预算。工具执行成功后先保存原始结果 journal，再作收据
及预览；存储失败不回报为执行失败，未知结果也不自动重放。

新任务只在新副本归档/reset epoch、result 和 history，移除旧的进行中压缩 journal 与旧故障状态，
修正 continuation 文件清单。原包和长期主动 memory 保留。同任务恢复复用已完成摘要，失败或不确定的调用不重放。

## 原文回查与主动记忆

- `history.jsonl`：append-only 的实际消息原文。恢复 checkpoint 和 pending 工具结果后先做
  幂等补录，保留相同消息的出现次数；流式扫描避免每次载入整个长期日志。
- `memory.jsonl`：Agent 主动记录的经验、决定与引用。它是 Agent 的声明，不替代科研证据。
- `recall(keywords,n,m,...)`：返回有原文位置的有界片段。轮边界同时处理 user turn 和完整
  模型工具批次；连续工具调用不能被错误地当成一个无限大的“轮”。

摘要、preview 和 spill 的控制引用指向的原文须存在且与声明一致。损坏尾部保留并明确报告，
缺失原文不能冒充成功索引。较早已归档的历史不应靠摘要凭空还原，按其来源路径回查。

## 验证范围

`test_harness_compaction.py` 覆盖原有 spill/Recall/memory；`test_fork_host_compatibility.py`
使用真实 FastAPI Host 和假 provider，覆盖专用角色/反馈边界、实际 token 预算和操作状态预留、
初始目标加连续工具调用、旧结果污染、归档-only 目标保留、配对/来源校验、恢复幂等与退出不发新调用。
这些隔离测试不是长期稳定性、真实摘要质量或研究性能改善的证明。

## 配置何时生效

`configs/context-400k.env.example` 给出主、worker 和 summary 都为 500000 的完整上下文配置。
这是本地待部署配置，不会自动修改现有 `.env`。已有显式 64000/32000 覆盖项仍会覆盖新默认值。
Host 在启动时构建预算；普通 Agent 输入热加载不会更新它。需要匹配的新 Host 和完整 Harness overlay，
再由 Harness 在正常请求前读取 `/context/config`。本地提交、修改模板或编辑磁盘源码都不会替换活动进程。

`A3_SUMMARY_INPUT_TOKENS` 已删除，配置该旧字段会明确报错，部署时须移除。
旧 Host/Harness 摘要协议不兼容；需要匹配更新，两者都不会因本地提交自动生效。
摘要请求状态按完整输入哈希保存，只有确认完成的答案可以复用；不存在 8/16 次持久化预算。
