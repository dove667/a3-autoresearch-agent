# 外界监督与运行干预

Version: 0.2.2

本文件面向用户、父助手与 Host 操作者，不是研究 Agent 的输入，不加入 input manifest。Agent 的反馈处理规则在阶段 Prompt，接口与状态技术事实在 execution；文档职责与装载链见 [Agent 输入管理](agent-inputs.md)。

## 低频弱监督与批准边界

正式运行前由部署方完成执行环境预检与预算配置；预算可分别设置限额或明确不限，实际配置留档。默认由研究 Agent 自主提出实验、选择候选、处理可恢复错误并判断验收。外界按实际进展低频查看摘要、轨迹、资源和阻塞；只在出现明确问题或有用的新信息时提供范围清晰的反馈，不逐步代替 Agent 设计和指挥全部实验。观察、建议与完成证据应分开，不能回注“已通过”标签代替实际执行。全部 worker 停止后再外部复核逐项结果。

每次热加载或中断前须获得用户明确批准，包括热加载输入、热加载反馈，以及停止/暂停运行来应用改动。父助手先说明目标 run、拟发送的具体内容或版本、理由、受影响身份/作业、预计影响和恢复方式；批准后只执行该范围。一次代码修改批准、先前的热加载批准或笼统的持续优化意向，不自动批准下一次运行干预。单纯查看状态或预览并不发布内容，也不能据此视为获准。摘要或目标身份变化时重新确认批准是否仍覆盖实际操作，不擅自扩大范围。

审批由外界用户与操作者负责；不让研究 Agent 审核外界是否获批，也不把本文件或审批流程复制进研究提示词。Agent 只需按当前输入、实际权限及收到的反馈核查并记录自身决定。

反馈应指出已核实的事实、来源、适用范围、建议及不确定性；保持现有科学规则。若要改变目标、验收或协议，明确提出相应版本变更，不用普通反馈暗改计分、种子划分或完成条件。保留旧版本与旧结果，不能看到结果后重写历史选择标准。记录实际人工参与，不把有指导的运行描述为全程无人干预。

## 人工干预必须说明

任何人工干预都应通过 human feedback 向受影响的研究 Agent 讲清楚，尤其是人工恢复、外部修复、输入更新和调度改变。说明实际改了什么、为何干预、哪些未改、证据与不确定性，以及希望它重新核对什么和继续什么；不能只改变进程或磁盘状态，假设 Agent 自然知道。没有活跃进程时，仅对仍符合恢复条件且经批准继续的任务，在恢复入口带入反馈；不为发送通知复活已完成任务；运行中按已批准的反馈入口投递。当前机制仅绑定一个主身份，涉及接任时须核对接收身份与交接材料，不假定自动广播。

该要求不授予新的干预权限，也不要求只读观察都注入反馈；仍遵循每次实际干预的明确批准。登记之后核对 forwarded 事件和对应模型调用的 human_feedback_ids，区分“已登记”“已送达”“已采纳”，没有送达时如实说明。不能把基础设施 smoke 或外部修复通知写成 Agent 的验收通过。

## 热加载版本化输入

按 [版本规则](agent-inputs.md#需要维护版本的内容) 修改源文件并递增版本；编辑不会自动影响运行中的实验。先预览：

```bash
uv run python -m runtime.local.reload_inputs "artifacts/rsi/<run-id>"
```

核对警告、原版本、新版本和内容摘要，将具体变更与影响交用户批准；获批后使用预览返回的完整摘要发布：

```bash
uv run python -m runtime.local.reload_inputs "artifacts/rsi/<run-id>" --confirm <预览摘要>
```

自定义 run 默认仍读取其冻结版本。要在获准后换为另一套完整目录，预览和确认两次命令都增加 `--agent-inputs-dir <完整目录>`；Host 仅允许保持当前阶段、profile 与文件名集合的替换，检查 UTF-8、符号链接、版本及内容摘要。目录参数只在操作者控制入口生效，Agent 无权选择来源。旧 revision 保留，新版本发布后恢复不依赖外部源目录。这个入口不更新 Agent 工作区中的技能副本或索引；如需更新它们，须在已批准范围内显式完成并核对实际版本。

确认绑定具体文件内容，预览后源文件变化会使旧摘要失效。操作者认证保存在 Host 私有状态，Agent 令牌不能更新输入。已发出的模型请求按旧版本返回，下次请求使用新版本；原对话与 Agent 代码不重写。热加载不会重建已有 Python 对象、切换模型或镜像；bootstrap 运行参数和固定基础设施代码变更通过停止/恢复应用，相关中断也须事先获批。

发布后检查 input manifest 的 active、revision/generation 和 input-events；按对应模型用量的 input_revision 核对实际采用版本。失败或回滚如实记录，不声称已生效。更多快照与历史记录见 [输入管理](agent-inputs.md#启动与恢复记录)。

## 恢复时加入人类反馈

恢复或为恢复而中断前，按上文确认用户批准的范围。环境修复说明或专家建议可以维护在同一个本地 `human-feedback.md` 中，每次覆盖内容。反馈文件由人类明确授权注入，普通历史报告与工具输出继续按数据处理。

```bash
bash scripts/start-rsi.sh \
  --resume-from "artifacts/rsi/<run-id>" \
  --feedback-file human-feedback.md
```

`--feedback-file` 仅用于恢复已经生成 Harness 的主 Agent；未提供时不会读取该源文件。当前实现要求 Harness 向 Gateway 发送完整消息历史，不支持仅用 `previous_response_id` 引用服务器端对话。反馈应说明已核实的变更、受影响作业与建议核查事项，不包含认证信息，也不替 Agent 宣称验收通过。

Host 读取当次 UTF-8 文本（最多 64 KiB），保存内容副本、SHA256 和反馈 ID，封装协议版本为 0.1.0。源文件不要求人为维护语义版本；每次显式注入的具体内容由摘要与反馈 ID 标识。同一身份最近一次反馈与文件内容一致时，重复指定不会新建注入事件。覆盖源文件不会自动改变正在运行的请求。

恢复后，反馈作为一条新的 user message 放在原有历史之后、下一次模型调用之前。Host 不改写旧 checkpoint、工具结果或原始轨迹，不拆开 function_call 与对应工具结果。暂停进程可能仍在处理恢复前的请求；反馈是否实际抵达，以后续模型请求的 human_feedback_ids 和 Host 的 forwarded 事件为准。forwarded 表示模型请求成功返回，不代表 Agent 已接受建议或完成了建议动作。

后续完整历史请求中，Host 在同一个历史边界保留该条反馈，每份有效上下文只有一条该反馈，不在每轮末尾反复追加。再次 resume 不指定文件仍会沿用已经登记的反馈。Harness 压缩或重建上下文时，Host 将反馈重新定位到当前完整历史末尾并记录 reanchored 事件；未完成的工具结果须先对齐。

同一个源文件便于维护，当次副本与事件仍保存在本 run 私有的 `.host/human-feedback/`，恢复与审查依赖这些记录。反馈只绑定登记时的主身份，不自动发给测试 worker 或后继主身份；主 Agent 按任务需要自行交接。原 run、身份和 Agent 的持久记忆保持不变。该人工反馈会影响后续执行，应在实验报告中如实标记人工参与。

## 运行中热加载人类反馈

Host 已运行新版反馈接口时，可以让实验继续执行，通过独立终端把同一个 `human-feedback.md` 中的最新内容送给当前主 Agent。先预览：

```bash
uv run python -m runtime.local.reload_feedback "artifacts/rsi/<run-id>" \
  --feedback-file human-feedback.md
```

命令显示正文、接收身份与摘要，尚不注入。核对正文、身份、摘要并取得本次用户明确批准后，使用显示的摘要确认：

```bash
uv run python -m runtime.local.reload_feedback "artifacts/rsi/<run-id>" \
  --feedback-file human-feedback.md --confirm <预览摘要>
```

正文或主身份变化会使旧摘要失效，须重新预览。操作仅限持有 Host operator 凭据的人类入口；普通 Agent 无权注入。源文件最多 64 KiB UTF-8，覆盖文件本身不会自动发送。Host 已暂停或仍运行旧代码时，需要先按正常流程恢复或重新部署；CLI 不会替你启动实验。

登记后，反馈会出现在当前主 Agent 下一次完整历史模型调用中。已发出的模型请求、工具和远程作业继续执行，不会即时打断。返回 `delivery=next_model_request` 表示登记成功、等待投递；可在 `.host/human-feedback/events.jsonl` 找到对应 `forwarded`，并在 `model-usage.jsonl` 用 `human_feedback_ids` 核对实际成功转发。主身份若在投递前退出或交接，反馈仍保留在原身份的记录中，不自动广播或改发。

内容留档、去重、恢复后沿用、工具结果配对及人工参与记录，与恢复时反馈共用同一机制。

## 干预后的核对

只核对本次操作是否生效及是否造成阻塞：输入发布检查生效清单，反馈检查登记和成功转发事件，中断检查实际进程/作业状态与恢复材料。`forwarded` 不等于建议被采纳，更不等于验收通过。若未投递、身份已交接或需要再次中断/热加载，先说明实际状态和下一步，再取得相应批准；不自动改发给另一身份或重复干预。

## 可选网页能力的配置与发布

Tavily 凭据只在本机 Host 的 `.env` 配置，不能通过聊天索取或回传；[配置指南](setup.md#可选研究网页网关tavily)说明位置和用量语义。搜索/fetch 不设 per-run 累计次数上限，持久计数跨身份和恢复保留；提供商额度与暂时性限流分开处理，Host 不查询账户余额、不自动重试或购买/升级。用户管理付费设置，若启用付费则可能产生费用，不保证免费。查看 `/web/status` 不进行真实搜索；本次实现与配置说明不授权付费调用或正式实验。

网关默认关闭，新代码、配置和阶段 Prompt 用于下一次经批准的新阶段二 run，沿用选定 H1，不重跑第一阶段，不自动作用于当前 run。发布 Prompt 也不会给已有 Harness 自动注册工具。外界仍只作低频、范围清晰的监督；每次反馈、热加载或中断须单独明确批准，不因已经批准实现网关而推定获准。

## 第二阶段持续研究的生命周期

Phase 2 goal/acceptance 0.4.0 将 A–D 定义为研究里程碑：完整科学证据标准不变，达到后冻结报告并继续研究，不因一次通过自动退出。共享 protocol 0.3.1 的计分、配对、留出集与预算规则未改。最终测试不是持续调参集；暴露结果参与选择时按原协议重新划分用途与登记未使用的最终测试集。

运行中顶层 outcome 使用 continue，已通过的阶段项保留其快照和证据。RunSupervisor 只等现有活跃会话，并在全部停止后读取 outcome；不会因 A–D passed 退出，也不会看到 continue 就启动下一轮。全体退出仍记 incomplete。持续运行须由现有主 Harness/交接链维持；没有新增守护进程、自动修复或恢复权限。正常等待不冒充外部 blocked。操作者停止、真实阻塞或预算/权限边界触发如实收尾，是否完整通过与收益分开报告。

此语义仅适用于新的第二阶段输入；G 等第一阶段任务仍须交付并正常退出。冻结的历史 run 不改写，运行中输入或反馈更新仍遵循上述明确批准和留档规则。
