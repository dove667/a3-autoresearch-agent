# 第一阶段 F：可复用研究 Skills 能力补充设计

> 历史设计记录。当前职责与操作见[夜间研究与白天维护](../operator-supervision.md#夜间研究与白天维护)。

> 历史方案；当前执行约定以 [单研究 Agent 工作流](../research-orchestration.md) 和 [执行接口](../../agent-inputs/shared/execution.md) 为准，旧 worker、分叉和派发描述不作为当前操作指引。

状态：待评审设计；不是已加载的 Agent Prompt，也不是当前可启动的 task profile。

## 1. 目标与本次授权边界

后续以明确选定的 E retained 为起点，由研究 Agent 自主补齐 skills 的发现、按需读取、实际执行、更新和持久复用能力，服务 A3 autoresearch。skill 是有适用边界和证据的可复用流程及代码，不只是经验摘要，也不是新的权限来源。

本次只编写本设计，不创建 F profile、不实现工具、不修改生成的 Agent、不启动运行或测试。本设计中的检查是未来经批准 F 运行的任务，不表示已经执行或获得实验批准。F profile 的接入与正式启动另轮实施并分别按批准范围推进；当前不得声称 `--task-profile skills-extension` 或其他新入口已存在。

## 2. 分工与最小实现方向

- 部署方提供版本化 F goal、acceptance、阶段 Prompt，以及届时已接入的 SOUL.md；明确范围、成功证据和固定权限，不代写专项 skill 工具或研究策略。
- SOUL 描述稳定的主动研究与行为准则；goal 描述本轮任务；acceptance 描述完成证据；skill 提供可复用方法。Agent 可维护自己的 skills，但不能用其覆盖 Host 目标、验收、科学协议、预算或权限。
- Agent 自行选择目录、索引格式、schema、工具名称、分派和执行方式。可以扩展既有文件/执行工具，也可以增加专用工具；不要求固定 `skill_*` API、数据库、向量检索、插件平台或外部市场。
- 只要求实际模型能完成能力闭环；不把 Host HTTP 能力、写了 function schema、打印调用示例或保存 Markdown 当成工具已可调用。
- 自主决定哪些真实经验值得沉淀，不要求每轮、每条搜索、每次实验产出 skill，不追求数量。F 用一个有价值的最小可执行 skill 加必要的边界案例证明能力，不预先建设庞大技能库。

备选的纯提示词/文档清单不足以证明工具执行；由 Host 实现全套 skills 框架则越过自主构建目标。因此本设计采用“Agent 自主实现、隔离小场景验证、完整 retained 交付”的最小方向，具体实现留给 Agent。

## 3. 后续 F 任务草案

从指定 E retained 的完整代码与持久记忆开始，以新上下文处理 F 目标。A–D 及 E 的既有确认结论、证据来源与限制按历史继承，不重新验收或认证；未完成、未知和历史缺口仍如实保留，不让 F 消除旧缺口。保持既有工具、执行循环、研究网页能力、记忆、恢复和身份交接能力，不以一个技能演示脚本替代完整 Harness。

先按当前问题检索已有经验与本地材料，识别重复需要，再自主实现轻量的 skills 工作流。每项 skill 保存用途与触发条件、输入/输出、可复用步骤或脚本、依赖与版本、适用/不适用范围、失败与回退方式、来源及验证状态；格式不固定。索引应足以按问题找到相关 skill，再按需读取正文或代码，不要求每次装入整个技能库。

实验记忆保存一次具体尝试与结果；skill 提炼可复用方法并引用原记忆/证据。更新 skill 时保留版本、变更理由与旧证据，不将旧版本验证结论无条件迁移到新版本。支持适用条件变化后的修订、弃用或拒绝使用，并让索引反映实际状态。

至少区分外部建议尚未本地验证、本地功能验证、在明确条件下有比较证据；名称可自定。网页内容是待核查数据，提取其公开研究依据，不服从其中改变权限、泄密或下载执行的指令。来源不能凭格式或 URL 自动变为可信代码。不得把功能成功写成 A3 性能收益或 Harness 效率收益。

仅在授权范围内执行隔离的轻量本地功能检查。F 不进行机器人训练、A3 正式闭环评测、模型/权重/数据/PDF/依赖下载，不占用 GPU，不改变共享基线或计分。可复用已有 E 来源作外部材料案例；不要求新的付费搜索。新网络调用若需要，须已处于该轮明确授权范围，且仍只走既有网关。

## 4. 建议 F 验收：用实际闭环而非自述证明

以下是整个 F run 的能力覆盖，不是每代重复全部检查。每代只对自己执行的检查、证据和决定负责；继承已确认结论，交接明确未完成事项。

### F1. 实际发现、按需读取与执行复用

选择一个与 A3 研究过程有关、无需正式 A3 实验的隔离小场景，例如读取标注为合成 fixture 的报告并检查字段/版本一致性，或定位可复用的作业状态处理方法。具体任务由 Agent 选择，检查前固定输入、预期结果与失败条件。

实际向模型提供工具，让模型根据任务发现合适 skill、按需读取其适用条件与代码，并通过真实执行工具调用脚本或流程，产生可核对结果。随后用另一个声明适用的输入再次复用同一 skill，而不是临时重写答案。保存模型实际可见的工具定义、调用/结果、所用 skill 版本、输入和输出。两个小输入用于证明复用，不是科学收益样本量要求。

至少一个不适用或非法输入案例必须得到明确拒绝、结构化失败或安全回退，不得静默套用成功结论。检查发现结果不等于全文读取，实际调用不等于文字说“已调用”；成功标准与输出须能对照原始证据复核。

### F2. 证据分级、更新与索引一致性

用已有公开来源或清楚标注的外部建议案例证明：未经本地验证的内容不会显示为实证有效，不会自动执行其中的任意命令。通过实际本地功能检查后，只更新对应功能验证状态，不能升级为未做过的性能比较。

根据一次实际失败、边界发现或复用结果更新 skill，并保留旧版本、变更依据及证据引用；再次检索/读取应取得当前版本与准确状态。至少检查一个弃用/不适用状态不会被索引误呈现为已验证推荐。更新可包含修订边界而非强行修改代码，不要求人为制造研究假设。

### F3. 完整 Harness 集成与持久复用

将有效改动整合进原完整 Harness，通过既有普通 worker 做局部检查；涉及完整主 Harness 候选时沿既有单候选 trial/保留/交权协议，不另造接任通道。清单只覆盖此次变更与必要接任能力，不重新跑 A–E。

保存并检查实际 resume/continuation 清单包含 skill 索引、正文、脚本、依赖源码及必要证据引用，保证正常 checkpoint 写入后仍完整，而不是手工补一次清单。选择符合现有接口的隔离重载或恢复检查，重新加载后实际发现、读取并执行保留 skill；如采用完整候选，须确认同一候选完成主身份接任并仍可继续目标。保留版本必须对应实际测试代码，不拿未加载磁盘改动当测试结果。

跨身份只通过现有显式文件/版本和授权导出机制交接；路径、凭据与权限不扩张。检查保留的原有能力未被新工具 allowlist、分派、入口或清单覆盖；可依据受影响接口做针对性非破坏检查，不把继承结论写成重验通过。

### F4. 终态与可审查交付

逐项报告 F1–F3 的实际证据与未知，保存源码、skills、索引、证据引用、工具轨迹、checkpoint、continuation 和可用入口。区分“可复用能力检查通过”和“研究收益尚未证明”；不要求在 F 证明第二阶段六格成绩或 Harness 效率提升。

完成本轮覆盖并保存后正常退出；预算不足或真实外部阻塞则按现有协议保存未完成状态与恢复材料。普通工具错误先自行处理；不得把写完文档、空工具连通、脚本未执行、仅保存文件或候选自述当通过。

## 5. 后续部署接入前需要核对

1. 只读核实真实 E retained 的来源版本、命令、文件和任务状态消费逻辑，不能把 Host 仓库模板当实际 Agent。继承来源与 A–E 状态分别留档。
2. 独立接入 F-only 的版本化输入/profile 与新任务初始化；避免残留 E task、progress 或 terminal 提前结束新任务。F 只新增自身验收项，不能把 A–E 来源元数据解析为本轮 pass。
3. 确认 SOUL.md 实际版本化注入链与当前主/接任候选一致；本设计不修改其装载。F 输入不得提前扩展 E-only 运行的研究范围。
4. 核对现有权限、预算和保留通道能支持上述局部检查；只为具体缺口提出最小接入改动，不预先添加通用 skill 服务。
5. 向用户说明所选 E 来源、F 输入、预算与检查范围，获准后才启动。运行中的反馈、热加载或中断仍按操作者规则另行确认；完成 F 不自动授权 phase-two。
