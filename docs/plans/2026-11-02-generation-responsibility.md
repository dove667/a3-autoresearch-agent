# 代际验收责任分域

## 用户裁决

每个版本的 H 主 Agent 只负责自己的实验过程：先提出假设，再执行，再决定是否保留，确认自身交接条件满足后才交权。后继可继承前任已确认结论，不为前任的结果与过去的合规过程负责。

## 设计与范围

- 两阶段 Prompt 明确本代闭环、已确认结论、证据引用与未完成任务的交接；移除最后一代重验整个历史的隐含责任。
- 前任历史缺口保留归属，不因换代消失，也不自动成为后继补审任务。接手明确未完成事项是新的执行责任；未知、未完成不能变成通过，整轮仍须如实报告缺口。
- 历史按当前问题按需查询，明确矛盾允许针对性核查，不要求读全消息或默认全历史审计。输入变化仅核对受影响结论的适用性。
- trial 候选先验证本次改动及接任能力，接任后开展自身研究，不必接任前完成整个 run。每代仍在交权前真实核查自己的闭环与接任清单。
- acceptance 区分整轮覆盖与代际责任；protocol 保持科学规则，已有匹配结论可继承，不因换代重复最终网格或已完成的配对比较。第一阶段原有最终复核仍保留，不扩为每代交接门槛。
- execution、架构、教程和输入维护说明同步。仅修改 Prompt、文档和离线测试，不改变运行实现、权限、审批边界或实际运行状态；不改写历史消息、输入或产物。
